# SFT v2: отбор обучающих данных судьёй по полному дампу

Цель — собрать обучающие ответы, которые лучше базы по качеству содержания (главный урок РК1), и сделать это один раз локально, чтобы в Colab только обучать.

## Что сделано

1. Взят весь дамп Gardening SE (17 860 вопросов, 25 421 ответ), а не только комнатные теги, и все ответы со Score ≥ 1, а не только лучший.
2. Детерминированные фильтры (`scripts/build_sft_pool.py`): закрытые вопросы, тег `identification`, картинки в ответе, ответ короче 200 символов, длина диалога больше 1536 токенов Qwen, вопросы из `plant_dev`/`plant_test` (исключены, чтобы оценка осталась сравнимой с РК1). Для вопросов с фото — дополнительно отсев, если текст вопроса ссылается на изображение («photo», «this plant», «what is this» и т. п.), для всех — если ответ ссылается на фото.
3. Судья для отбора — `anthropic/claude-haiku-5.5` (`src/data/target_judge.py`, рубрика `sft_target_v1`). Он намеренно другой семьи, чем судья оценки `gpt-4o-mini`, чтобы не учить модель нравиться оценщику. Те же 4 критерия 0–2 плюс: домен, `question_text_sufficient` (фото заменено маркером `[IMAGE REMOVED]`, при сомнении — false), `answer_self_contained`, `assistant_style` 0–2, `critical_error`.
4. Отбор (`scripts/select_sft_data.py`): текст достаточен, ответ самодостаточен, не off-topic, без critical, factual = 2, сумма ≥ 7/8, style ≥ 1, не больше 2 ответов на вопрос. Для вопросов с фото дополнительно отбрасываются вердикты, где судья в обосновании колеблется («relies on removed image», «mostly sufficient»).

Стоимость: $3.31 за 12 638 вердиктов плюс калибровка. Три пары судья не смог оценить (обрезанный JSON), они пропущены.

## Калибровка судьи (39 dev-вопросов, без ориентира)

| Источник | gpt-4o-mini (оценка РК1) | Haiku 5.5 (отбор) |
| --- | --- | --- |
| Лучший ответ SE | 4.79 | 4.18 |
| База Qwen2.5-3B | 7.00 | 4.00 |
| S1 | 3.36 | 2.03 |

Оба судьи считают S1 худшим, но Haiku не видит большого преимущества базы над форумом. Ранговая корреляция судей — 0.62 на ответах SE и S1 и только 0.23 на ответах базы. В разобранных расхождениях прав Haiku: про мох в горшке с базиликом ответ SE верный («поверхность постоянно сырая»), а база уверенно пишет, что мох полезен и привлекает полезных насекомых; gpt-4o-mini поставил базе 7, а SE — 5. Вывод для отчёта: часть разрыва «база 7.0 против форума 4.8» в РК1 — предпочтение gpt-4o-mini к гладкому LLM-стилю. Падение S1 это не отменяет.

Под фильтр отбора не проходит ни один из 39 dev-ответов базы (у SE — 6 из 39). Отобранные цели в среднем получают 7.18, старый `plant_train` — 4.79 (factual = 2 лишь у 27%); из 743 старых пар новый фильтр прошли 90.

## Принятые решения

1. **Тема — все растения.** Гипотеза: советы из разных областей усиливают друг друга. Для проверки к `plant_dev/test` (комнатные, как в РК1) добавлены `garden_dev/test` — по 40 вопросов не-indoor доменов из отобранного пула (ориентир для судьи — лучший отобранный ответ); все их ответы исключены из train. Правило выбора чекпоинта считает среднюю оценку судьи по plant_dev ∪ garden_dev. Оговорка: garden-вопросы взяты из прошедших фильтр, то есть они в среднем яснее и с хорошим ориентиром.
2. **Формат «3 шага» убран** из обучения и оценки (в данных ~3% списков). Автопроверка теперь `no_invented_experience` (`src/eval/checkers.py`, тесты в `tests/test_checkers.py`): на ответах РК1 база проходит 78/78 (dev+test), S1 — 73/78; провалы S1 — «I have seen», «I've had», «I've never seen».
3. **Стиль — только промпт.** Системный промпт (`configs/model.yaml`) дополнен: «Answer in a neutral expert voice: do not claim personal experience or plants and gardens of your own.» Он одинаков для обучения и оценки; база в новой серии переоценивается с ним же, поэтому числа РК1 напрямую не сравнимы.

## Риски

1. **Конфликт стиля.** 20.5% обучающих ответов (217 из 1 060) проваливают автопроверку: «I use», «I've had», «in my area». Промпт просит одно, данные учат другому — SFT может перебить промпт, как в S1. Дешёвые выходы, если на dev это проявится: исключить эти пары (останется ~840) или переписать только их (~$0.1).
2. **Судья оценки.** gpt-4o-mini, судя по калибровке, переоценивает гладкие ответы базы. Для следующей серии стоит добавить второго судью на dev, оставив gpt-4o-mini для сравнимости с РК1. Haiku как судья оценки нежелателен: им же отбирались данные.
